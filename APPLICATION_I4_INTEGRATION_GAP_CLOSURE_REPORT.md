## Changes

Inspected the existing planner/validator, production calculator and conversion registry contracts, task engine and chat SSE, message tool timeline, mixed-input helper and verified-unpublished artifact lifecycle. Kept the existing agent framework and security gates.

- **Backend dependency evidence:** calculator-expression references previously selected a prior successful calculator result without explicitly requiring its recorded `evidence_verified` flag. The engine now requires that flag before substituting the result. If a calculator contract has no verifier, a later dependent calculation fails rather than reusing the unverified value. The existing registry, schema validation and result verification remain authoritative. A focused test removes the verifier from a synthetic registry and confirms the second step never dispatches and the task fails.
- **Tool progress:** matching any same-name result to any start made two successive calculator calls appear finished during the second call. The message timeline now tracks starts/results in order per tool; an outstanding call shows Running while streaming and Outcome uncertain after interruption. A result missing its success field is unknown rather than successful. The activity header says Results received rather than implying the whole task completed. The expandable header is now a keyboard-focusable button, and raw argument JSON is no longer shown. Tests server-render actual `MessageItem`; interaction and accessibility remain unverified in a mounted browser. Stream events lack invocation IDs, so tracking assumes ordered starts/results per tool; duplicates or concurrent same-tool events remain a contract limitation.
