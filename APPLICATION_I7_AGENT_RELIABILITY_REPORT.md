# I7 Agent reliability

**I7: PASS for the scoped synthetic cases below; production remains NO-GO.** No live Ollama, mounted browser, normal Windows socket loop or deployed application was tested. This is not a guarantee against all model fabrication or concurrent registry changes.

## Defects and changes

Inspected production Ollama decoding/timeouts, planner and validator, registry/result verification, agent execution/interrupt wrapper, task storage/recovery, chat SSE and existing frontend state tests. Three confirmed gaps were addressed:

1. The planner previously extracted a bracketed array from surrounding prose, silently accepting model narration alongside executable instructions. It now accepts a single JSON array or a single fenced JSON array, rejects duplicate object keys, non-finite constants, unexpected step fields and oversized output. Malformed plans fail through the existing planner/task failure path. Tradeoff: a model that wraps an otherwise valid plan in prose now receives a planning error rather than automatic repair. Existing validator/registry and approvals remain authoritative.
2. The tool-call parser could silently pick the first of multiple tagged calls and silently remove JSON trailing commas. Tagged calls now reject multiple/malformed tags, duplicate JSON keys, extra top-level fields and non-finite JSON values; malformed tagged JSON is not reinterpreted as a function call. Supported single tool forms remain. This does not constitute a complete grammar or prove rejection of every ambiguous untagged output.
3. A planned reasoning step could complete after a provider stream ended without a completion marker, and did not explicitly close that stream. It now requires a terminal marker and uses `aclosing`; interruption raises an error and the existing task wrapper records `FAILED_INTERRUPTED`. No automatic retry or replay was added.

Additionally, when the text tool loop sees the narrow phrase pattern “I/we ran/executed/used [the/a] calculator/tool/script/code” without a recorded tool call, it prefixes a warning that no tool execution was recorded. It does **not** detect every possible fabrication and does not independently verify arbitrary model prose. Such prose still appears as model text; it is not emitted as a verified tool result or task completion receipt. Real model testing and a broader evidence-aware presentation remain future work.

## Fixture and workflow evidence

`tests/fixtures/i7/model_outputs.json` contains synthetic plain text, calculation, dependent/cross-tool plans, refusal, malformed/duplicate/prose-wrapped plans, duplicate tagged calls, a fabricated claim and incomplete/duplicate terminal stream frames. The new tests exercise these categories through the actual planner, engine and Ollama parser with in-memory providers; existing I4/I6 route tests cover real production calculator/conversion execution with fake planner outputs (42→126 and 10.0→10000.0 m). Not every fixture value is independently exercised, and none is captured live Ollama output.

New negative tests establish no tool dispatch for refusal/malformed/unsupported/duplicate/prose-wrapped plans, excess plan length and unexpected fields, or duplicate tagged calls. Bare and fenced valid plans still execute. Existing focused tests cover invalid outputs, unverified dependencies, pre-dispatch cancellation and blocked report grounding. Duplicate terminal provider frames are stopped at the first terminal; interrupted provider streams fail. The interrupted reasoning test verifies closure and `FAILED_INTERRUPTED` using the immediate, non-suspending coroutine driver. An independent regression checks interrupted synthetic side effects are not automatically retried; it does not prove rollback or real disconnect handling. Separate ownership tests cover cross-owner denial and expired process-local proof after restart. Approval resume and document/artifact gates remain blocked.

No frontend code was changed. Existing simulated-hook tests cover repeated events, approval lock, stale callbacks and terminal/error presentation; server-render tests cover restricted output. They are not mounted React or browser interactions. Dynamic tool replacement after validation, plan mutation races, comprehensive cancellation of all native/provider operations, generalized fabricated-success detection, unknown stream formats, process crashes and live restart remain unverified. The provider has a bounded timeout in its existing code; no new retry was introduced.
