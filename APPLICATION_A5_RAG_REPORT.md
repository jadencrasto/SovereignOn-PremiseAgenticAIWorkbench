## Implemented

- Existing parser now uses the entire content in its deterministic filename/content identifier and records SHA-256; its prior first-1,024-byte identifier could collide for differing files. The ingestion service replaces the parser ID with the existing registry-reserved ID; parser IDs generated by older standalone callers differ, so callers persisting those IDs require migration/compatibility review before activation. This change does not deduplicate registered documents across filenames or owners.
- Rejects empty/oversized inputs, invalid PDF signatures, invalid or expanded-size-limited DOCX archives, binary signatures/NULs presented as text, and oversized extracted text. Extracted-text checking happens after parsing; it is not a CPU/memory isolation boundary. No macros or scripts are executed. PDF and DOCX dependencies parse untrusted content in process and still need sandboxing and resource-limit assessment before production use.
- Chunk windows have bounded size, stable sequence IDs and configurable nonnegative overlap. Text-derived `[Page N]` markers no longer create page metadata because arbitrary document text cannot prove a page number. The different chunking requires a fresh, authorized re-index before compatibility with prior indexes can be claimed.
- The existing embedding provider validates nonempty finite numeric vectors and consistent dimensions within a service instance, sanitizes HTTP failure details and handles timeouts. A failed batch does not return a partial result. The existing ingestion path additionally validates each vector and checks the provider model name against the configured index model before writing. Model names are not immutable model digests; existing-index dimension/model identity and cross-process compatibility are not independently verified.
- The document screen displays blocked/unknown capability state and suppresses upload and empty-index claims in those states. It does not establish operational retrieval.

## A5.2 — source validation and citations: PARTIAL

The existing `Retriever`, `VectorStore`, `DocumentService` and `document_search` security gates remain closed. Their direct retrieval entry points now raise a blocked error rather than returning an empty successful search; the registry still denies the tool before execution. Embedding/index errors in the retriever now propagate as errors. Existing security-test expectations for blocked reads were adjusted accordingly; this intentionally changes the low-level blocked-call contract. Other list/detail APIs and the agent's no-document context paths retain their existing fail-closed behavior.

`backend/rag/grounding.py` adds **non-authorizing**, isolated evidence selection and grounding helpers. Synthetic candidate records require document/chunk IDs, filename, content, sequence, source revision, finite cosine distance and matching declared index/model versions. Candidates are bounded, sorted by increasing distance with stable tie-breaks, deduplicated, top-k limited, and filtered through an injected scope callback. Conflicting duplicate records and malformed values fail. This callback is an interface for a future authoritative check, not an existing production authorization mechanism. The real `Retriever` does not yet use this helper for protected results; its existing positive-path metadata handling and source authorization must be replaced or safely integrated before any gate is opened. Matching version/model strings do not verify a real index, model digest, dimensions, record ownership or freshness.

The bounded synthetic context assigns fresh request-scoped citation IDs and omits unverified page data. A fake model's references must resolve to the current context; unknown or absent references fail. All prompt passages, including uncited ones, are retained as document/revision dependencies and checked again after generation. Revocation between context construction and validation therefore fails in the synthetic fixture. The returned dependencies are not yet integrated into authorized persistence or protected assistant replay, and no atomic authorization guarantee exists across final presentation. Reference validation does **not** verify factual entailment, validate model-written filenames/pages in prose, or establish authenticated evidence. No model output is currently routed through this foundation in production.

The chat source card now withholds source metadata and previews until an authorized presentation contract exists. This avoids claiming Chroma provenance or presenting text-derived page numbers. Actual validated citation rendering is unavailable; React server-rendered tests check the withheld/missing state, not an interactive browser.
