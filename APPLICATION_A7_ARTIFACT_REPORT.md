# A7.1 report and artifact foundations — PARTIAL

Date: 2026-11-13. Overall A7: **PARTIAL**; production remains **NO-GO**.

## Existing architecture and changes

Inspected the existing DOCX/XLSX generators, `artifact_storage`, `artifact_verifier`, artifact routes and presentation rules, ToolRegistry approval/owner guards, agent planner, capability-gated artifact UI, A5/A6 reports and Phase 1.5.3H artifact-integrity report. Existing DOCX/XLSX generators use opaque exclusive files and return a digest; artifact preview/download and verifier access remain denied when provenance cannot be revalidated. There was no existing PDF generation tool. No production tool, route or authorization gate was enabled.

Added `backend/tools/report_contract.py`: bounded title, sections, source-attributed versus model-interpretation labels, tables and format; source citations must occur in a separately supplied ID/filename map and dependency set. The map is **not** authorization or freshness evidence, and citation membership does not prove factual support. The contract creates arguments for existing DOCX/XLSX tools but is not wired into the production agent. Report content is labelled as source-attributed and not independently verified. XLSX output accepts one table, and PDF/DOCX accept multiple tables. Existing generators are also callable through their original less-restrictive schemas; this contract has not replaced them.

The existing XLSX generator now writes leading `=` strings as literal text for title, headers and cells, preventing those values from becoming workbook formulas. Numeric values remain numeric. This does not cover all possible downstream spreadsheet/export behaviors or establish full formula-injection protection for unrelated output formats.

Added an isolated `backend/tools/pdf_report.py` renderer, not registered as an agent tool or API. It uses locally available PyMuPDF, generates an ASCII-only PDF with text-based table rows, and verifies extracted lines using pypdf before writing via existing exclusive artifact storage. Non-ASCII text and oversized documents are explicitly rejected. PDF layout and visual appearance were not rendered or reviewed; table cells are text rather than a verified accessible table. PyMuPDF is an optional local dependency for this isolated function, not a verified deployment dependency.

## Format and integrity evidence

- **DOCX: synthetic generation/readback verified.** Existing `docx_create` generated a real file in a temporary directory; python-docx reopened it and checked title, section text, source ID/filename and table dimensions/cells. Existing verifier returned its hash and observed expected content. A later byte modification changed the digest and caused structural verification to fail.
- **XLSX: synthetic generation/readback verified.** Existing `xlsx_report` generated a real workbook reopened by openpyxl; tests checked numeric cells and literal formula-like title, header and row values, plus source metadata. Worksheet configuration is the existing fixed `Compliance Report` sheet; complex spreadsheet features are not claimed.
- **PDF: isolated synthetic generation/readback verified.** The new non-registered renderer produced an actual PDF; pypdf extracted the title, source, report text and table-row content. ASCII-only support, absence of visual layout testing and optional dependency prevent claiming general production PDF support.

Artifact filenames/IDs use the existing exclusive opaque storage and SHA-256 is compared to file bytes in tests. The existing design writes directly to a unique file, can leave an orphan after interruption or verification failure, and does not provide atomic publication, durable recovery, independent tamper resistance or safe automatic cleanup. The injected PDF write failure produced no success result; that test did not establish cleanup of a partially written real file. No generated fixture was published or made available for preview/download. The DOCX/XLSX generator return values precede independent verification, and their public execution contract does not yet enforce verify-before-success.

## A7.2 — isolated verified report lifecycle: PARTIAL

Added `backend/tools/verified_report.py`, an isolated wrapper around the existing report contract, DOCX/XLSX generators, PDF renderer and artifact storage. It validates the contract and source-map membership before staging; creates a unique staging directory beneath a caller-supplied private parent; invokes the existing generator; checks opaque ID/extension, regular-file identity, bounded size and digest; independently reopens the output with python-docx, openpyxl or pypdf; checks expected content and table data where implemented; and rechecks file identity and bytes. It returns checked bytes and dependencies with state `verified_unpublished`. This state establishes neither semantic correctness nor authorization, publication, task completion, durable recovery or rollback resistance. The caller-supplied source map remains non-authorizing. PDF keeps its ASCII-only and unverified visual-layout limitations; the PDF renderer's own line checks precede wrapper readback.

Known completed staging files are unlinked only when their observed nonzero file identity still matches; empty staging directories are removed without recursive deletion. If the generator fails before returning an identity, or identity/cleanup cannot be established, the file/directory is left quarantined. Tests cover an injected unknown orphan and preservation of an unrelated sibling. This assumes a trusted private staging parent and does not establish race-free protection against hostile OS writers, Windows reparse-point substitution, cleanup after process crash, power-loss durability or cross-process recovery. Cancellation of an asynchronously suspended fake generator removed an empty stage; existing synchronous file generation cannot be interrupted at arbitrary points by asyncio cancellation. No final filesystem publication or atomic rename is claimed.

The wrapper is **not** wired into production tools, the registry, agent or TaskStore. Existing DOCX/XLSX schemas and execution paths remain compatible and can still report generation before independent verification. They do not enforce the new structured report contract; consequently A7.2 cannot pass and production task completion must not be described as verified artifact completion. Source revalidation is unavailable and no untrusted source map is promoted. No preview/download or approval gate was changed.

A fake-provider test through the existing planner and task engine submitted a natural-language report request and selected `docx_create`. It stopped at the existing grounded-source precheck, before approval, because no permitted source evidence was available; no file was generated. A test initially expected an approval event and failed; the assertion was corrected to reflect the observed fail-closed precheck, not to bypass it. Resume remains blocked. Existing A7.1 registry tests independently cover owner and approval denial.
