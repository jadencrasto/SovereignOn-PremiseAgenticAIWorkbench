## Artifact error hardening

`backend/api/artifacts.py` now projects path-validation and text/DOCX/XLSX/PDF preview exceptions through existing `public_error('OPERATION_UNAVAILABLE')`, preserving 400/422 statuses and suppressing exception chaining in responses. Existing code had no diagnostic logging in these handlers; no new logs containing exception data were introduced. Current `_is_artifact_accessible` denial and collision logic were not changed. Successful artifact presentation and authorization remain out of scope. The tests that exercise latent branches temporarily mock authorization in-process and do not enable artifact reads in the application.

Before the fix the new synthetic artifact regression returned **3 failed**, demonstrating raw path/exception disclosure in preview, download and DOCX parsing when the latent branches are made reachable in a test. After the fix the following targeted command ran (no Chroma harness was executed):
