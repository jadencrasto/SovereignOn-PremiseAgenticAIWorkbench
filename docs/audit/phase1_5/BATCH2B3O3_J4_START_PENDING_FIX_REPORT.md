# J.4 START_PENDING control assertion

Native evidence showed START_PENDING, STOP returning 1052, and a test failure caused by the old assertion requiring only 1061. Microsoft documents 1052 for an unacceptable control and 1061 for a control that cannot be sent in a pending state. The fixture reports zero accepted controls during START_PENDING and STOP/SHUTDOWN only during RUNNING. This explains why treating 1052 as an unconditional failure was too narrow; it does not independently establish the service state at the exact instant of the original STOP call.

The runner now queries immediately before STOP and requires an existing START_PENDING service, accepts only 1052 or 1061, queries again and permits only START_PENDING or STOPPED, then requires STOPPED with Win32 1066 and service-specific initialization deadline code 13. The existing bounded wait applies when still pending. Other control results, missing service, unexpected states, final statuses and timeouts fail. Separate queries cannot be atomic with the control request, and a slow machine may fail closed due to the five-second initialization deadline. J4 diagnostic forwarding includes the new unexpected state category. Cleanup and snapshot requirements remain unchanged.
