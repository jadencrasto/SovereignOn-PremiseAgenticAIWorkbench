# Security and trust boundaries

Static review only, not a penetration test. Browser -> API authentication/CSRF -> role permissions -> planner/tool registry -> filesystem/container and model endpoint are distinct trust boundaries. Uploaded text and model responses are untrusted; `backend/agent/injection_guard.py` applies heuristic wrapping/detection, not a formal guarantee. See ISSUE_REGISTER.md for findings.

Conversation session IDs are globally enumerable and deletable by a user with VIEW_DATA (`backend/api/chat.py:1208-1238`), and the client supplies the ID on chat (`chat.py:86`); `backend/agent/memory.py:127` has no owner field. This exposes cross-user destruction and may allow history reuse. Validate exploitation in an isolated authenticated two-user environment.

Defaults are development mode, `auth_enabled=False`, and `backend_host=0.0.0.0` (`backend/config.py:43,56,127`); this combination must not be exposed on a network. Production validation requires auth and Docker unless explicitly overridden (`backend/utils/config_validation.py:43,186`). Default subprocess mode explicitly is not true OS isolation (`backend/tools/code_execution.py:15`); Docker mode uses network none and no mounts (`code_execution.py:385`). Do not interpret AST filtering as a sandbox boundary.

Document clearance is attached at upload and used on retrieval (`backend/api/documents.py:89`; `backend/rag/retriever.py:143`); document-level and group ownership beyond clearance are not established. Approval hash binding exists (`backend/agent/approval.py:38,306`) but live concurrency/replay/authorization verification remains outstanding. Upload reads entire request before size validation (`backend/api/documents.py:82`, `backend/rag/service.py:138`), a possible memory DoS; ingress limits are unverified. External fonts contradict a fully self-contained UI (`frontend/index.html:8`; `frontend/src/index.css:1`). Configurable model endpoint and dependency telemetry require deployment egress controls; OS firewall and Chroma behavior were not tested.

The project needs session isolation tests, policy for user/group document ACLs, restricted service accounts, secrets/transport review, backup/restore, log confidentiality and retention, dependency scanning in an approved offline environment, network policy verification and a complete adversarial review. No external scan or confidential data transmission was performed.
