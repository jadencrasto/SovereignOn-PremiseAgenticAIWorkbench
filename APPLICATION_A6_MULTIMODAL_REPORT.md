# A6.1 multimodal foundations — PARTIAL

Date: 2026-11-13. Overall A6: **PARTIAL**. Production remains **NO-GO**.

## Existing architecture and changes

Inspected the existing agent multimodal stream and production chat route, image processor, visual schemas and grounding verifier, provider abstraction/router, A5 parser and grounding foundation, XLSX report tool, chat composer, A3/A5 reports and focused regression tests. The existing image path uses a vision provider followed by a reasoning provider; image support was implemented but live inference and browser behavior were unverified. Document ingestion/retrieval and artifact access remain security-blocked. The XLSX tool generates reports; it is not a safe spreadsheet reader.

The existing image processor now uses Pillow verification and decoding for PNG, JPEG and WebP, rejects malformed, animated, mismatched and excessive images, and enforces a 16-million-pixel ceiling in addition to the existing byte and side limits. The chat route reads at most 10 MiB plus one byte from the parsed upload and rejects a missing filename. Multipart parsing can occur before the route-level read; this is not evidence of a total ingress-memory limit. Image bytes are now processed without writing to the image directory; attachment metadata does not imply durable image retention or later image recovery. Synthetic source identifiers remain server-generated and conversation authorization is checked before processing.

Vision routing now verifies that the configured model declares the requested capability; configuration is not proof of actual availability. Non-streaming vision calls have a 60-second deadline and reject empty/invalid response content. The visual context labels the configured model, not a hard-coded model. Provider failure now produces a stream error instead of a successful terminal event; model-produced visual interpretation is not represented as a verified measurement. The separate unused vision-stream helper has not received the same deadline/terminal-event verification.

Added an isolated byte-to-data CSV/XLSX reader with input, archive-expansion, sheet and cell bounds. It preserves XLSX sheet names, typed values, empty cells and formula text; formulas are never evaluated. External workbook links and macros are rejected. Deterministic summaries compute count, mean and maximum only from actual finite numeric cells, and report missing and nonnumeric cells. CSV cells remain text and are not automatically converted to numbers. The component exposes no API, file access, agent tool or artifact route. XLSX parser resource use and supported workbook features are not comprehensively verified or sandboxed.

The composer clears a previous attachment when a replacement is invalid and remounts on conversation changes to clear its draft attachment. Existing capability warnings and cancellation controls are retained. Real mounted-browser switching and object URL lifecycle remain unverified.

## Synthetic integration and restrictions

In-process tests exercise the actual FastAPI chat route, production agent engine and image processor with fake vision and reasoning providers. They check image transfer, a completed response, cross-owner denial and provider failure without a completion event. Separate synthetic tests exercise actual A5 PDF/DOCX parsers, a fake-model PDF summary with request-scoped citations, DOCX source association and spreadsheet calculations. These do not provide authorized production document summarization, comparison, mixed document/image analysis, source freshness, durable multimodal provenance or live semantic grounding. Image-derived assistant outputs remain subject to existing fail-closed provenance rules; no source-independent provenance is granted by these changes. Multiple images in one request are unsupported.

## A6.2 — internal multimodal composition: PARTIAL

Added `backend/multimodal/workflow.py`, an isolated, non-authorizing composition helper. It reuses the existing image processor, vision provider service/router interface, A5 document parser and A6 spreadsheet reader. It accepts a bounded question and up to four filename/byte inputs with a 12 MiB aggregate limit. Each input receives a new opaque request identity, owner/conversation labels, SHA-256, type and processing status. Supported individual parser limits remain in force; extracted or generated context is capped at 20,000 characters. Invalid request shapes, missing scope, denied scope and excessive total inputs fail; individual processing failures are represented without raw exceptions. If any input fails, the overall result is `failed` and all partial values and dependencies are withheld. Cancellation propagates through vision inference.

Synthetic tests exercise two DOCX source associations, document/XLSX values with deterministic numeric summaries, text/image inference through a fake vision provider, denied scope, simulated revocation, invalid input, aggregate limits and provider failure/cancellation. All successfully processed input IDs are included as response dependencies. Vision output is explicitly labelled model-generated; no model interpretation establishes measurements or tool completion. The helper's injected conversation callback is **not** a trusted authorization service, and neither caller-provided owner labels nor hashes establish authority. It is not wired to a production route or agent and provides no durable provenance, document-level authorization, true revocation freshness or permission to use protected sources. The question itself is not represented as a separate input record. Synchronous document and spreadsheet parsing is not interruptible mid-call or sandboxed; aggregate compressed-byte limits do not prove bounded parser memory or multipart ingress.

This is preparation, not a completed mixed-input answer workflow: document/document and document/spreadsheet tests verify source association and parsed calculations, but do not generate or validate a comparative answer; citation validation and provenance persistence are not integrated with this helper. Formula evaluation remains disabled, CSV numeric strings are not automatically treated as numbers, and the helper does not handle multiple-image reasoning as a single provider call. Per-input failures currently share a generic error category. Existing frontend image attachment and switching guards were retained; no multiple-upload interface or new public document route was introduced.
